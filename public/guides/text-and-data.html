Text utilities without data confusion: formatting, Base64, hashes and passwords

ToolNez editorial · Updated 25 October 2026

Several developer utilities transform text, but their purposes differ. A nicely formatted object is not necessarily correct data. An encoded secret is still a secret. Understanding the transformation helps you choose the tool and check the result.

Format JSON while keeping the source

JSON formatter parses valid JSON and serializes it with spacing or a compact layout. JSON requires double-quoted keys and strings; comments and trailing commas are not supported. Formatting can reveal the structure, but it does not validate a business schema or whether a price, date or email address is correct.

Try {"name":"Ada","active":true} as a simple sample. A very large unquoted integer can lose precision in JavaScript. Keep identifiers such as long account numbers as strings when the data format permits it, and retain an unmodified source if exact numeric text matters.

Base64 provides representation, not secrecy

Base64 encodes bytes into a limited text alphabet. The word “hello” becomes aGVsbG8=. Anyone can decode it; there is no password or encryption key. Do not post a Base64-encoded token assuming it has been hidden.

Encoded length grows to groups of four characters for every three input bytes. A file therefore becomes roughly one third larger before any wrapper or line breaks. Use this tool for small transport examples, not as a compression strategy.

Compare hashes against a trusted value

Hash calculator produces a SHA digest of exact text or file bytes. Choose the same algorithm used by the publisher of an expected checksum and compare the whole digest. Adding a newline changes the input and its hash.

A matching checksum supports an integrity check only if the expected value came from a trusted source. A malicious page can distribute both a modified file and its matching hash. Hashes are not reversible encryption, and plain SHA is not a suitable password-storage scheme.

Generate unique passwords

Password generator uses browser cryptographic randomness. Choose a long length and character sets accepted by the service, then save a unique password in a trusted password manager. Enable multifactor authentication where available.

The strength display models a hypothetical guessing process. Real risk also depends on reuse, phishing, rate limits and how a service stores passwords. A strong generated string used on many accounts is still a poor practice.

Review ordinary text transformations

Case conversion can damage acronyms; accent removal can change names; duplicate-line removal can delete intentional repeated text. Word counts depend on how a product defines a word. Keep a source copy and use the destination portal count for a hard publishing limit.

The Markdown editor saves a local draft while you type. Clearing browser site data removes it, so export the .md when the notes matter. Externally linked images may contact their hosts when previewed. Use synthetic samples while learning and review the saved output before replacing real data.
